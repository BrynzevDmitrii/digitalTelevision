# Моя планета: тестовое задание (frontend)

Три страницы по макету Figma: список материалов, детальная страница и создание материала.
Десктопная и мобильная версии (мобильная до 744px включительно).

**Стек:** Nuxt 4 и Vue 3, TypeScript, стили на Less, редактор Tiptap.

## Установка и запуск

Нужно: **Node.js `^22.22.3` или `^24.15.0`** (этого требует Nuxt 4.6) и **npm 11 и новее**.
На npm 10.8 установка падала с ошибкой `Cannot read properties of null (reading 'edgesOut')`, на npm 11 всё ставится без флагов.

```bash
npm install
cp .env.example .env     # в Windows PowerShell: Copy-Item .env.example .env
```

В `.env` впишите персональный код (alias) из письма с заданием:

```
NUXT_MATERIALS_ALIAS=ваш_код
```

Без него сервер ответит ошибкой 500 `NUXT_MATERIALS_ALIAS is not set`. Файл `.env` в репозиторий не попадает.

```bash
npm run dev          # разработка, http://localhost:3000
npm run typecheck    # проверка типов (vue-tsc)
npm run build        # сборка
npm run preview      # запуск собранной версии
```

Для запуска собранной версии на хостинге переменная `NUXT_MATERIALS_ALIAS` задаётся в окружении сервера.

## Как устроен проект

```
app/
  pages/            index (список), materials/[id] (детальная), materials/create
  components/       AppHeader, BaseButton, MaterialCard, RichTextEditor, BackLink, AppIcon
  components/header кнопки хедера: «Создать историю» и «Сохранить»
  composables/      useMaterials: общий список материалов
  utils/            разбор и форматирование даты
  assets/styles/    переменные, сброс стилей, типографика, брейкпоинты
server/api/materials/   прокси к внешнему API (index.get.ts, save.post.ts)
server/utils/           адрес API, очистка HTML
shared/                 типы Material и проверка длины полей (видны и клиенту, и серверу)
```

### Стили

- Все цвета, шрифты, отступы и размеры лежат в CSS-переменных: [variables.less](app/assets/styles/variables.less). Имена цветов повторяют названия стилей из Figma.
- Мобильная версия включается переопределением переменных в одном блоке `.mobile({ ... })` в том же файле, поэтому в компонентах почти нет отдельных мобильных стилей.
- Брейкпоинт (744px) задан одной Less-переменной в [breakpoints.less](app/assets/styles/breakpoints.less). В `media query` CSS-переменные использовать нельзя, поэтому здесь Less.
- Шрифты Source Sans 3 и Futura PT лежат в `app/assets/fonts`. Futura PT платный шрифт, лицензия на нём остаётся за правообладателем.

## Ответы на вопросы из задания

### Как получаются данные для детальной страницы

Отдельного эндпоинта нет, поэтому из трёх вариантов выбран **общий стор** (`useMaterials`, построен на `useState` Nuxt), с запасным запросом списка.

- Список загружается один раз и хранится в состоянии, которое Nuxt переносит с сервера в браузер. Переход со списка на детальную страницу не делает новых запросов, материал ищется в уже загруженном списке по `id`.
- При прямой ссылке или обновлении страницы (F5) состояния ещё нет, и список загружается прямо на детальной странице, на сервере. Это тот же вариант «получить список и найти элемент по route», он включён как запасной.
- Если материала в списке нет (например, список устарел), список один раз перезагружается, и только после этого отдаётся 404.
- Варианты, которые не подошли: **передача через props** невозможна между разными страницами и ломается при обновлении страницы. **Запрос всего списка на каждую детальную страницу** без кеша лишний.
- Для создания материала это важно ещё и потому, что сервер на `save` отвечает только `{ success, id }`. После сохранения список обновляется, и открывается `/materials/{id}` уже с данными, которые вернул сервер.

### Проверка длины `title` и `short_description`

Правила лежат в одном месте: [shared/utils/validateMaterial.ts](shared/utils/validateMaterial.ts). Лимиты: `title` не более **80** символов, `short_description` не более **255**. Заголовок обязателен (пробелы по краям обрезаются), дата должна быть корректной.

- **В форме** функция вызывается при отправке, ошибки показываются под полями. Рядом с каждым полем есть счётчик `N/80` и `N/255`, он краснеет при превышении. Атрибут `maxlength` намеренно не используется: иначе пользователь просто не мог бы ввести лишнее и не видел причины.
- **На сервере** та же функция вызывается в роуте `POST /api/materials/save` перед пересылкой запроса. При ошибке возвращается `422` с полем `errors`. Так лимиты не обойти прямым запросом.

Папка `shared/` в Nuxt 4 доступна и клиенту, и серверу, поэтому правила не дублируются.

### CORS

Внешний API не отдаёт CORS-заголовки для `localhost`, поэтому браузер не может обращаться к нему напрямую. Запросы идут через **серверные роуты Nuxt (Nitro)**:

- браузер вызывает свой `/api/materials` (список) и `/api/materials/save` (создание);
- сервер Nuxt сам обращается к `https://naukatv.ru/api/test/materials/{alias}`. Для запросов между серверами CORS не применяется;
- alias хранится в `runtimeConfig` на сервере и не попадает в клиентский бандл.

Почему не `routeRules` или `devProxy`: они помечены в документации Nitro как dev-инструмент или экспериментальные. Серверные роуты работают одинаково в разработке и в продакшене, и в них есть место для проверки данных и очистки HTML.
Расширения браузера и публичные CORS-прокси не использовались.

## Решения, которые стоит знать

- **Редактор:** Tiptap со `StarterKit`. Набор блоков по заданию: параграф, `h1`–`h3`, цитата. На сервер уходят оба формата: `description_html` и `description_json`. Оформление редактора не дорабатывалось, как разрешено в задании.
- **Безопасность HTML:** `description_html` выводится через `v-html`, поэтому сервер очищает его перед отдачей (`sanitize-html`, [cleanHtml.ts](server/utils/cleanHtml.ts)): остаются только теги, которые умеет делать редактор.
- **Даты:** сервер возвращает дату как `2026-10-16 09:51:00` (UTC, без пояса), а при создании принимает ISO. Утилиты в [materialDate.ts](app/utils/materialDate.ts) понимают оба формата. Для отображения («21 сентября») часовой пояс зафиксирован как `Europe/Moscow`, чтобы дата на сервере и в браузере совпадала и не было ошибки гидратации.
- **Сортировка:** список сортируется на клиенте по дате, новые выше.
- **Кнопка в хедере** зависит от страницы: на списке и детальной «Создать историю», на странице создания «Сохранить» (мобильная версия: иконки). Страница задаёт её через `definePageMeta({ headerAction })`, а сама кнопка «Сохранить» отправляет форму атрибутом `form`.
- **Карточки в списке** одной высоты (сетка с `grid-auto-rows: 1fr`), описание обрезается до 4 строк с многоточием.

## Известные ограничения

- Автотестов нет, проверка типов запускается командой `npm run typecheck`.
- Размеры страницы создания сверены с макетом не полностью (карточка редактора).
- Редактор не поддерживает перетаскивание блоков и меню `+` из макета: по заданию это не требовалось.
